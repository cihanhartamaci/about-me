How I work with AI

Daily practice from an Integration Architect’s desk — EDI bridges, RESTful APIs, NetSuite SuiteScript, and the habits that keep projects and learning moving.

Practical, not theatrical

My day job is integration: mapping trading-partner flows, shaping API contracts, and keeping WMS and ERP systems talking cleanly. AI sits in that loop the same way a sharp editor sits next to a writer — accelerating drafts, challenging assumptions, never replacing judgment on production behavior.

I do not outsource architecture. I use assistants to move from idea to working sketch faster, then verify against real payloads, partner guides, and the constraints of live EDI and API platforms.

  • Build

    Coding assistants on the line

    When I am deep in SuiteScript, Python, or SQL for integration jobs, coding assistants help draft boilerplate, suggest test cases, and surface edge conditions I might skim past. I still review every mapping, every retry path, and every partner-specific quirk before anything ships.

  • Design

    Clearer EDI & API shapes

    Designing Order-to-Cash X12 sets, EDIFACT flows, or REST gateways benefits from a second voice that asks “what fails at 2 a.m.?” I use AI to compare approaches, tighten interface contracts, and keep hybrid sync designs honest about latency and idempotency.

  • Docs

    Specs, runbooks, learning

    Clear documentation is part of the integration. Assistants help turn rough notes into partner-readable specs and internal runbooks. The same loop speeds up learning a new API or revisiting a standard I have not touched in months.

  • Life

    Same habit off the clock

    Off the clock, the habit stays practical: personal projects, language practice, planning travel notes, or untangling a sticky problem from the week. Less theater, more leverage — then back to friends, coasts, and quiet frames.
